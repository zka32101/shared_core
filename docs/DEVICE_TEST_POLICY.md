# 実機テスト方針（全アプリ共通）

小学コレシリーズ・yourwish の**今後すべてのアプリ・リリース**に適用する実機テストの方針。
個別コードの点検ではなく、「何を・どこで・どの頻度で・何をもって合格とするか」を定める。
上位文書: [`DEV_PLAYBOOK.md`](DEV_PLAYBOOK.md)（環境分担・マネタイズ・セキュリティ）

最終確認: 2026-09-29

---

## 0. 原則

1. **人が見るのは「判断が要るもの」だけ**。画面の網羅、例外の検出、ログの確認は機械にやらせる。
2. **安い手段から順に使う**。静的チェック → CI エミュレータ → 無料のクラウド実機（Play の起動前レポート / Test Lab）→ 手元の実機。
3. **ストアから配信されたバイナリで最終確認する**。署名・課金・Google サインイン・App Check は、Play の内部テストや TestFlight 経由でしか本番と同じ動作にならない。
4. **debug では合否を判定しない**。release（最低でも profile）で見る。debug で出る赤い画面は、release では**灰色の空白**になって見逃しやすい。
5. **不具合は二度起こさない**。見つけた不具合は、再発を防ぐ自動チェック（ship-cycle か integration_test）を追加してから閉じる。

## 1. テストレベルと実施タイミング

| Lv | 名称 | 手段 | 実施場所 | タイミング | 目安時間 |
|---|---|---|---|---|---|
| L0 | 静的チェック | `ship-cycle`（preflight / store-check） | クラウド・ローカル | 毎 PR | 数秒 |
| L1 | 全画面ツアー | `integration_test`（§3）+ スクリーンショット | CI エミュレータ | 画面・状態に関わる PR | 5〜10分 |
| L2 | スモーク | `device-check.sh` + §2 のスモーク項目 | Windows ＋ 実機 | リリース候補ごと | 10分 |
| L3 | 連携テスト | §4 のマトリクス | 実機（ストア配信版） | 連携部分を変えた時・リリース前 | 30〜60分 |
| L4 | 異常系・エラー注入 | §5 | 実機 | リリース前（毎回全部ではなく変更に関係する行） | 20〜40分 |
| L5 | 端末網羅・非機能 | 起動前レポート・Test Lab・§6 | クラウド実機 | 内部テストに上げた時に自動 | 自動 |
| L6 | 段階公開の監視 | Android vitals / Crashlytics | 本番 | 公開後 72 時間 | 監視のみ |

**リリースの流れ**: L0/L1 green → 内部テスト（Play）/ TestFlight に上げる → L5 のレポートが自動生成 → ストア配信版で L2・L3・L4 → 段階公開（L6）。

## 2. スモークテスト（10分・毎リリース候補）

ストア配信版を実機に入れ、`device-check.sh` のログ判定と合わせて行う。

1. 新規インストール → 起動 → 初回導線（チュートリアル・同意画面）を完了できる
2. メイン機能を 1 周できる（1 ステージ / 1 クイズを最後まで）
3. アプリを終了して再起動 → 進捗・コイン・設定が保持されている
4. 保護者ゲート → ショップ / Paywall が表示される（購入はしない）
5. 広告が 1 回表示される（テストデバイスで）
6. バックグラウンドに回して 5 分後に復帰 → 固まらない・状態が崩れない
7. logcat（Xcode のコンソール）に FATAL / FlutterError / 未処理の例外がない

1 つでも失敗したら、L3 以降に進まない。

## 3. 全画面網羅（画面台帳 × 状態 × 表示条件）

### 3.1 画面台帳
各アプリの `integration_test/screen_catalog.dart` に**全画面をルートとして列挙**する（正本）。
新しい画面を追加する PR では、台帳への追記を必須とする（レビュー時の観点にする）。

### 3.2 状態の網羅
各画面について、該当する状態をすべて描画させる:

| 状態 | 作り方 |
|---|---|
| 空（データ 0 件） | テスト用に override した Provider で空リストを返す |
| 読み込み中 | Future を完了させない fake |
| 通常 / 大量データ | 100 件以上（スクロール・性能確認） |
| エラー | 例外を投げる fake → エラー表示と再試行ボタンが出るか |
| オフライン | 接続状態を offline にした fake |
| 無料 / プレミアム | 購読状態の Provider を切り替え（広告の出し分けも確認） |
| 未ログイン / ログイン済み | Auth の fake |
| 制限到達 | スクリーンタイム上限・デイリー上限・コイン不足 |

### 3.3 表示条件
**ライト/ダーク × 文字倍率 1.0 / 2.0 × 小型スマホ（360×640）/ タブレット（1280×800）**。
全組み合わせではなく、「全画面 × 通常」＋「全画面 × 文字 2.0 × 小型」の 2 周を基本にする。

### 3.4 自動判定とスクリーンショット
ツアー中に `FlutterError.onError` を捕まえ、**RenderFlex overflow・例外・画像の読み込み失敗が 1 件でもあれば失敗**にする。
各画面のスクリーンショットを保存し、CI の artifact として一覧画像（コンタクトシート）にまとめる。人は一覧を 1 分眺めて、見た目の崩れだけを確認する。

```dart
// integration_test/screen_tour_test.dart（雛形）
final errors = <FlutterErrorDetails>[];
FlutterError.onError = errors.add;
for (final s in screenCatalog) {           // screen_catalog.dart の全画面
  for (final state in s.states) {           // 空 / エラー / プレミアム ...
    await tester.pumpWidget(ProviderScope(overrides: state.overrides, child: s.build()));
    await tester.pumpAndSettle(const Duration(seconds: 2));
    await binding.takeScreenshot('${s.name}_${state.name}');
    expect(errors, isEmpty, reason: '${s.name}/${state.name}: ${errors.map((e) => e.exception)}');
  }
}
```

## 4. 連携テストマトリクス

連携ごとに**正常 / 失敗 / 復帰**の 3 点を確認する。「正常に動く」だけでは不十分。

| 連携 | 正常 | 失敗・境界 | 確認手段 |
|---|---|---|---|
| Firebase Auth | 匿名ログイン → 起動ごとに同じ uid | 再インストール後の復元、アカウント連携、ログアウト後のデータ分離 | uid をログで比較 |
| Firestore | 読み書きが反映される | **オフラインで操作 → 復帰時に同期**、ルールで拒否された時にエラー表示が出る（無言で失敗しない） | Firebase コンソール |
| Remote Config | 配信値が反映される | 取得失敗時に**アプリ内の既定値**で動く | 機内モードで初回起動 |
| Analytics | 主要イベントが届く | — | DebugView（`adb shell setprop debug.firebase.analytics.app <pkg>`） |
| Crashlytics | テストクラッシュが届く | 非致命エラーが記録される | Crashlytics ダッシュボード |
| プッシュ通知 (FCM) | 前面 / 背面 / 終了状態で受信し、タップで該当画面に遷移 | 通知権限を拒否した時の案内、Android 13 以降の権限ダイアログ | Firebase コンソールからテスト送信 |
| AdMob | バナー・リワードが表示され、リワード付与は 1 回だけ | 読み込み失敗時に UI が崩れない、**プレミアム会員には一切表示されない**、子ども向けタグが効いている | **Ad Inspector**、テストデバイス登録 |
| UMP 同意 | EEA 端末で同意フォームが出る | 拒否しても広告以外の機能は使える | debugGeography=EEA |
| 課金 (RevenueCat / Billing) | 購入 → 特典反映 → 再起動後も維持 | **キャンセル・保留・復元・期限切れ・別端末で同じアカウント**、購入中にアプリを終了 | Play ライセンステスター / Sandbox（更新が短縮される） |
| 保護者ゲート | 購入・外部リンク・設定の前に必ず表示される | 不正解・キャンセルで先へ進めない | 目視（全導線） |
| クロスプロモ / 外部リンク | ストアが開く | ゲートでキャンセルしたら開かない | 目視 |
| Google サインイン | ストア配信版でログインできる | `DEVELOPER_ERROR` にならない（アップロード鍵と Play アプリ署名鍵の SHA-1） | **ストア配信版でのみ確認可** |
| アプリ間連携（shared_core） | 同じユーザーが 2 アプリで進捗・バッジを共有 | 片方だけ古いバージョンでも壊れない | 2 アプリを同じ端末に入れる |
| アップデート | **旧ストア版 → 新版に上書き**してデータが保持される | スキーマ変更時の移行 | 旧版の APK/IPA を保管しておく |

## 5. 異常系・エラー注入チェックリスト

| 分類 | 操作 | 期待する挙動 |
|---|---|---|
| 通信 | 機内モード / 低速（Android の開発者オプション、iOS の Network Link Conditioner） | タイムアウト後にエラー表示と再試行。無限ぐるぐるにならない |
| 通信 | **処理の途中で**機内モード（保存・購入・報酬付与の途中） | 二重付与や消失がない。復帰後に整合している |
| 連打 | 購入・報酬受け取り・送信ボタンを連打 | 1 回分しか処理されない |
| プロセス終了 | 開発者オプション「アクティビティを保持しない」→ 背面 → 復帰 | 画面・入力が復元される、またはトップに安全に戻る |
| 端末の時刻 | **時刻を進める / 戻す**、タイムゾーン変更、日付をまたぐ（05:00 リセット） | デイリーボーナスや連続日数を不正に稼げない。リセットが 1 回だけ起きる |
| 権限 | 通知・カメラ等を拒否 →「今後表示しない」 | 設定アプリへの案内が出る。クラッシュしない |
| ストレージ | 空き容量がほぼない状態 | 保存失敗時にメッセージが出る |
| 画面 | 回転 / 分割画面 / 文字倍率最大 / ダークモード切替 | レイアウトの崩れや状態の消失がない |
| 上限 | スクリーンタイム上限にちょうど達する / 超える | ロック画面になり、保護者ゲートで解除できる |
| アカウント | ログイン中にサーバー側で uid を無効化 | ログイン画面に戻る |

エラーの確認方法:
- Android: `adb logcat *:E flutter:V` を流しながら操作する（`device-check.sh` がパターンで判定）
- iOS: Xcode の Devices and Simulators → Open Console
- 共通: Crashlytics の非致命エラーと、Firebase コンソールのルール拒否数を、テスト前後で比較する

## 6. 端末マトリクス（最小構成）

| 枠 | 目的 | 手段 |
|---|---|---|
| 低スペック Android（RAM 2〜3GB・サポート最小 OS） | 性能・メモリ・ANR | 手元の実機（Windows に接続） |
| 最新 Android（15/16・16KB ページ） | 新しい OS の挙動・16KB ページ | CI エミュレータの 16KB イメージ / Test Lab |
| Android タブレット | レイアウト | 起動前レポート / Test Lab |
| 小型 iPhone（SE 系） | 画面の狭さ | 実機または Simulator |
| 最新 iPhone / iPad | 新しい iOS・iPad レイアウト | TestFlight + 実機 / Simulator |

**無料で使える自動実機テスト**（低リソースで優先的に使う）:
- **Play Console 起動前レポート**: 内部テストトラックに上げるだけで、実機 12 機種を Robo が自動巡回し、クラッシュ・アクセシビリティ・スクリーンショットを報告する。ログイン画面や保護者ゲートで止まる場合は Robo スクリプトかテスト用の認証情報を設定する。[公式](https://support.google.com/googleplay/android-developer/answer/9842757)
- **Firebase Test Lab（Spark プランは無料）**: 1 日に仮想端末 10 回・実機 5 回。1 回あたり最大 4 端末。L1 の全画面ツアーを実機で回すのに使う。[公式](https://firebase.google.com/docs/test-lab/usage-quotas-pricing)

## 7. 非機能の合否基準

| 項目 | 基準 | 測り方 |
|---|---|---|
| クラッシュ | テスト中 0 件。本番のユーザー体感クラッシュ率は **1.09% 未満**（Play の不良基準） | Crashlytics / Android vitals |
| ANR | テスト中 0 件。本番は **0.47% 未満** | Android vitals |
| コールドスタート | 低スペック端末で 3 秒以内に最初の画面 | `device-check.sh` の Displayed 時間 |
| フレーム落ち | 主要画面のスクロールで目立つカクつきがない | `flutter run --profile` + DevTools |
| メモリ | 10 分操作しても増え続けない | DevTools の Memory |
| アプリサイズ | 前回より +10% 以上増えたら理由を記録 | `flutter build appbundle --analyze-size` |
| アクセシビリティ | タップ領域 48dp 以上、主要ボタンにラベル | 起動前レポート / Accessibility Scanner |

[Android vitals の基準](https://support.google.com/googleplay/android-developer/answer/9844486)

## 8. 子ども向けアプリ特有の観点

- 保護者ゲートがない外部への出口（ストア・Web・メール・SNS 共有・購入）が**ひとつもない**こと。全導線を台帳で確認する。
- 広告: 誤タップしやすい位置（ボタンの直近）にない。問題の回答中に出ない。表示内容が年齢に合っている（Ad Inspector で子ども向けタグを確認）。
- 名前・学年以外の個人情報を入力させない。自由入力欄がある場合は、保存・送信先を確認する。
- 音量・振動・点滅: 急な大音量や激しい点滅がない。

## 9. 記録と引き継ぎ

- 結果は **PR か Issue にコメント**で残す（クラウドとローカルのセッションが相互に読めるように）。

```markdown
## 実機テスト結果 vX.Y.Z+N（ストア配信版 / 端末: Pixel 6a Android 16, iPhone SE3 iOS 26）
- L2 スモーク: ✅ 7/7
- L3 連携: ✅ Auth / Firestore / 広告 / 課金（購入・復元・キャンセル）、⚠️ 通知（背面から遷移しない → #123）
- L4 異常系: ✅ 通信断・連打・時刻変更、❌ 購入中にプロセス終了 → コイン二重付与（#124）
- L5 起動前レポート: クラッシュ 0 / 警告 2（タップ領域）
- 判定: ❌ #124 修正後に再テスト
```

- 不具合 → Issue → 修正 PR で、**静的に検出できるなら ship-cycle へ、画面や状態に関わるなら screen_catalog / integration_test へ**回帰テストを追加する。
- 公開後 72 時間は Android vitals と Crashlytics を確認し、基準を超えたら段階公開を**停止**する（10% → 50% → 100%）。

## 10. 更新ルール

- 審査リジェクトや本番障害が起きたら、該当する節に 1 行追記する。
- 外部の基準（vitals の閾値・Test Lab の無料枠など）は `DEV_PLAYBOOK.md` と同じく 90 日ごとに公式ページで再確認する。
